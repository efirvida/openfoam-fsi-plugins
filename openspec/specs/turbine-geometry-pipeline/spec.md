# Turbine Geometry Pipeline Specification

## Purpose

Defines the shared geometry pipeline at `turbinesFoam/geometry/` that generates
per-component STL surfaces from committed gmsh `.geo` sources driven by a Python
generator (`makeGeometry.py`), together with per-component metadata JSON and
provenance. The pipeline is deterministic and regenerable via
`makeGeometry.py --check` (mirroring `makeElementData.py` stale detection), and
is laid out to accommodate blade STLs in S2 without rework. S1 produces the
nacelle/hub STL (consumed by `nacelleSurfaceSource`) plus its metadata and
provenance; blade STL generation is deferred to S2.

## Requirements

### Requirement: Deterministic gmsh and Python generation

The pipeline MUST generate per-component STL files from committed sources driven
by `makeGeometry.py`. The `nacelle` component MUST remain gmsh-driven from its
committed `.geo` source with the pinned gmsh policy. The blade component MUST be
generated by a committed pure-Python builder. Every component MUST be
deterministic: regenerating from the same committed inputs MUST reproduce
byte-identical STL files (matching sha256).
(Previously: generation came only from gmsh `.geo` sources and blades were deferred.)

#### Scenario: Regeneration is byte-identical

- GIVEN the committed sources and generator inputs for a component
- WHEN `makeGeometry.py` regenerates the STLs
- THEN the output sha256 matches the committed STLs exactly

#### Scenario: Nacelle remains gmsh-driven

- GIVEN the committed `src/nacelle.geo` and the pinned gmsh
- WHEN the nacelle component is regenerated
- THEN its STL and metadata are unchanged and the gmsh version policy still applies

#### Scenario: Blade uses the Python builder

- GIVEN the committed blade inputs
- WHEN the blade component is regenerated
- THEN it is produced by the registered pure-Python builder without gmsh

### Requirement: Per-component STL output

The pipeline MUST emit one binary STL file per component. The nacelle STL MUST
remain produced. S2 MUST produce exactly one blade STL for the Phase VI rotor
(`phaseVI_blade`) because the rotor's two blades are identical, and the layout
MUST NOT reserve per-blade `blade0/1/2` outputs.
(Previously: nacelle only, with blade ×3 output reserved for S2.)

#### Scenario: Nacelle STL produced

- GIVEN the geometry pipeline
- WHEN the nacelle component is generated
- THEN the committed binary nacelle STL is present

#### Scenario: One blade STL serves both blades

- GIVEN the generated blade component
- WHEN the artifact layout is inspected
- THEN exactly one `phaseVI_blade` STL exists and no `blade0/1/2` STL is expected

#### Scenario: Per-component separation

- GIVEN the pipeline layout
- WHEN the output structure is inspected
- THEN each component (nacelle and blade) has its own STL output path

### Requirement: Metadata JSON

The pipeline MUST emit per-component metadata JSON recording the data a consumer
needs. For the nacelle this MUST remain per-node normals and areas. For the
blade it MUST record one entry per canonical triangle with a normal, an area, a
`radial_station`, and a `chord_fraction`, replacing the reserved null blade
mapping.
(Previously: the blade station/chord fields were reserved as nulls.)

#### Scenario: Nacelle metadata emitted

- GIVEN a generated nacelle STL
- WHEN the metadata directory is inspected
- THEN a nacelle metadata JSON records per-node normals and areas

#### Scenario: Blade metadata populated

- GIVEN a generated blade STL
- WHEN its metadata JSON is inspected
- THEN every node entry carries numeric `radial_station` and `chord_fraction` values and no reserved-null blade mapping remains

### Requirement: Provenance

The pipeline MUST include a `PROVENANCE.md` recording, for each generated
component, the source references, the generator route and version, and the
sha256 of the inputs. The nacelle row MUST keep its paper source; the blade row
MUST cite the Phase VI geometry source and the committed S809 coordinates
instead of the deferred MEXICO rotor tables.
(Previously: the blade row deferred to MEXICO and to S2.)

#### Scenario: Provenance present and complete

- GIVEN the geometry pipeline output
- WHEN `PROVENANCE.md` is inspected
- THEN each component records source references, generator route/version, and input sha256

#### Scenario: Blade source updated

- GIVEN the blade provenance row
- WHEN it is inspected
- THEN it cites the Phase VI geometry and the committed S809 coordinate dataset, not the deferred MEXICO tables

### Requirement: `--check` regenerability

`makeGeometry.py --check` MUST detect when a committed STL, metadata, or
provenance file no longer matches what the current inputs regenerate, MUST exit
non-zero on mismatch, and MUST NOT modify committed artifacts. For components
generated by a pure-Python builder, `--check` MUST NOT require a runnable gmsh.
(Previously: `--check` always required the pinned gmsh.)

#### Scenario: Clean tree passes

- GIVEN a geometry tree generated from the current inputs
- WHEN `makeGeometry.py --check` runs
- THEN it reports no stale artifacts and exits zero

#### Scenario: Stale STL detected

- GIVEN a committed STL that was hand-edited or left behind by an input change
- WHEN `makeGeometry.py --check` runs
- THEN it reports the stale STL and exits non-zero

#### Scenario: Check mode is non-destructive

- GIVEN a geometry tree with a stale artifact
- WHEN `makeGeometry.py --check` runs
- THEN the committed artifacts are left unchanged

#### Scenario: Blade check without gmsh

- GIVEN a host without a runnable gmsh
- WHEN `--check --component phaseVI_blade` runs
- THEN the blade artifacts are verified byte-identically and the exit code is zero

### Requirement: Pure-Python CI-safe test

The pipeline MUST be testable with pure-Python tests that regenerate and check
sha256 without a solver and without OpenFOAM. `test_nacelle_data.py` MUST keep
covering the nacelle, and a blade data test MUST cover the blade component.
(Previously: the nacelle data test only.)

#### Scenario: Data tests run without OpenFOAM

- GIVEN a Python environment with the test dependencies and no OpenFOAM
- WHEN `pytest` runs the geometry data tests
- THEN they pass, verifying deterministic regeneration and provenance presence for both nacelle and blade

### Requirement: Component builder registry

The pipeline MUST select the generation route per component from a committed
registry: gmsh-driven components (nacelle) keep the pinned-gmsh path, non-gmsh
components (blade) use the registered Python builder, and the component-name
policy, deferred/reserved names, and CLI error messages MUST derive from that
registry.

#### Scenario: Route selected per component

- GIVEN a registered component
- WHEN generation or `--check` runs
- THEN the component's registered builder route is used

#### Scenario: Unknown component rejected

- GIVEN a component name that is not in the registry
- WHEN the CLI is invoked
- THEN it exits non-zero and lists the available components
